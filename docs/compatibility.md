# 실제 서버와 장비 호환성 검증

릴리스 후보는 아래 필수 조합의 실제 실행 결과를 확인한 뒤 승인한다. 루프백 테스트, 크로스 컴파일 성공, 실장비 검증은 각각 별도 증거다. `미검증`은 `미지원`과 다르다.

## 기록 형식

각 실행에 날짜, 담당자, 앱 태그와 커밋(작업 트리 변경 포함), 클라이언트 OS 빌드와 아키텍처, 서버/장비 제품과 버전, 인증 조건, 절차 ID, 기대 결과, 실제 결과, 로그·화면 경로를 기록한다. 계정은 테스트 전용으로 만들고 고객사 주소·계정·암호·개인 키는 기록하지 않는다.

## 최소 필수 조합

| ID | 대상과 인증 조건 | 절차와 기대 결과 | 현재 실제 결과 |
|---|---|---|---|
| SSH1 | Windows x64·ARM64, macOS arm64·x64 → 실제 OpenSSH, 키 파일·에이전트 | 서버 버전과 클라이언트별로 로그인, `printf` 결과 확인, 로그아웃·재접속 | Ubuntu CI → OpenSSH 9.6p1에서 키 파일 로그인·셸 출력 통과. 배포 대상 클라이언트의 실제 OpenSSH·에이전트 조합은 미검증 |
| SSH2 | 같은 클라이언트 → OpenSSH, 비밀번호와 공개 키 → OTP | 저장 비밀번호 준비 → OTP 오답·재시도·취소 → 재접속. OTP 저장 UI와 자동 제출 없음, 취소 후 서버 인증 요청 없음 | 실제 OpenSSH 미검증. Windows ARM64의 russh 루프백과 실제 GUI에서 키 → OTP 정상·재시도·취소 통과 |
| SSH3 | OpenSSH 점프호스트, `-L/-R/-D` | 바스천·목적지 구분, 각 경로 정상 통신, 탭 닫은 뒤 리스너 종료, 바스천 인증 취소 후 목적지 연결 없음 | 실제 OpenSSH 미검증. russh 루프백 통과 |
| CON1 | 테스트 라우터/스위치 Telnet, UTF-8·CP949 | 장비 모델·펌웨어 기록. 한글 출력·자동 로그인·CR/LF·줄바꿈·취소 확인 | 미검증 |
| CON2 | USB 시리얼 어댑터와 테스트 장비, 9600/115200 8N1 | 어댑터·드라이버·장비 버전 기록. CON1 반복, 케이블 단절 후 재접속 | 미검증 |
| ZM1 | lrzsz와 실제 장비의 `rz/sz` | 0바이트·한글 이름·큰 파일 양방향 전송, 해시 일치, 취소 후 기존 파일 유지 | 장비 미검증. 기존 lrzsz CI 유지 |
| SF1 | 실제 OpenSSH SFTP, 쓰기 허용 테스트 계정 | 한글 경로와 3 MB 다중 청크 파일 왕복 후 바이트 일치. 별도로 1 GiB 파일의 해시·처리량 기록 | Ubuntu CI → OpenSSH 9.6p1에서 한글 경로 3 MB 왕복·바이트 일치 통과. 배포 대상 클라이언트 조합과 1 GiB 시험은 미검증 |
| SF2 | OpenSSH SFTP, 읽기 전용 폴더·기존 파일 | 권한 오류·덮어쓰기 취소·전송 중 단절. 기존 파일 해시 유지, 임시 파일 정리 | 실서버 미검증. 기존 russh 파일 보존·취소 테스트 통과 |
| RDP1 | Windows 테스트 VM, NLA/NTLM | OS 빌드·NLA 정책 기록. 인증서 최초 확인·변경 거부, IME 한글, 양방향 클립보드 | 미검증 |
| RDP2 | RDP1과 별도 RD Gateway | 인증서·사용자·게이트웨이 변경, 해상도 전환·탭 재활성화 중 취소 | 미검증 |
| APP1 | 배포 ZIP: Windows x64·ARM64, macOS arm64·x64 | 실제 해당 아키텍처 OS에서 다운로드·압축 해제·첫 실행, 설정 저장·재시작·업데이트 안내 | 이번 개발 빌드 Windows ARM64 GUI만 검증. 다른 OS/아키텍처·깨끗한 OS는 미검증 |

RDP Kerberos 인증은 현재 지원 범위에 포함하지 않는다. 위 표의 다른 미검증 항목을 지원 불가로 해석하지 않는다.

## 자동 실행

```powershell
cargo test --locked --workspace
```

Ubuntu CI에서는 `openssh-server` 설치 뒤 `sh scripts/test-openssh.sh`가 테스트 전용 계정·호스트 키·클라이언트 키·loopback 데몬을 만들고 실제 공개 키 로그인, 셸 출력, 한글 경로 SFTP 왕복을 확인한다. 실패하면 서버 로그를 출력한다. 일반 `cargo test`에서는 이 환경 의존 테스트를 명시적으로 ignored 처리하며, CI에서는 `--ignored`로 실행한다. 하네스 추가만으로 실서버 검증 통과로 기록하지 않는다.

## 릴리스 승인과 보류

릴리스 담당자가 후보 태그를 고정하고 플랫폼별 실행자를 지정한다. 실행자는 위 기록 형식으로 결과를 제출하고, 담당자는 CI와 실제 배포 파일의 서명·체크섬 결과를 대조한다. 필수 조합의 실패는 보류한다. 필수 조합이 미검증이면 검증을 수행하거나 해당 플랫폼/기능의 지원 범위를 릴리스에서 명시적으로 낮춘 뒤 재검토한다. CI 통과로 미검증 칸을 통과로 바꾸지 않는다.

실패는 재현 조건·정제한 로그·화면과 함께 결함 이슈로 연결한다. 장비·서버 버전이 바뀌면 해당 행을 다시 실행한다. [PR 197 CI](https://github.com/playok/playterm/actions/runs/42040505752)에서 Ubuntu의 실제 OpenSSH 및 macOS의 자동 테스트는 통과했다. 장비, macOS 배포 앱 및 네이티브 Windows x64 배포 앱의 실제 실행 증거는 없어 #194 전체 완료 조건은 충족하지 않았다.
