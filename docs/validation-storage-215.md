# 오류 복구와 저장 권한 검증 (#215)

- `random_id`는 OS CSPRNG 오류를 `io::Result`로 반환한다. 기본 프로필·템플릿은 ID 없는 초안이며, 실제 생성·복사·폼 제출·가져오기·옛 파일의 ID 보완은 오류를 호출부로 전달한다. ID 없는 초안은 저장소에 넣지 않는다. UI 폼과 가져오기 결과·상태 표시가 실패를 사용자에게 전달한다.
- ID 난수 실패를 테스트 스레드 안에서 주입해 프로필/템플릿 생성, ID 보완, 복사, 파일 로드와 원자적 저장이 패닉 없이 실패하고 원본 파일을 보존함을 확인했다. 이 주입은 `cfg(test)` 전용이며 실제 앱에서 OS RNG 자체를 고장 낸 시험은 아니다.
- SFTP 취소 맵의 poison은 남은 신호를 실패 처리해 대기 중인 요청을 깨우고 맵을 비운 뒤 복구한다. 등록/취소/제거 각각의 poison과 후속 작업을 시험했다. 영향받은 전송은 완료/사용자 취소로 표시하지 않고 실패를 알린다. 기존 실제 요청 취소·파일 보존 테스트도 유지한다.
- Unix의 볼트 저장은 임시 파일을 처음부터 0600으로 만들고, 원자적으로 교체한 결과도 0600을 유지한다. 일반 설정 파일과 Windows 권한 처리는 기존대로다. 임시 파일과 기존 느슨한 모드의 교체, 볼트 생성·갱신·삭제·옛 KDF 재해시를 Unix 전용 테스트로 검사한다. Windows 로컬에서는 이 Unix 테스트를 실행하지 않으며 macOS CI에서 결과를 확인한다.

2026-11-06 Windows ARM64에서 locked 전체 워크스페이스 테스트와 strict clippy/fmt를 통과했다. 실제 앱에서 새 사이트를 저장하고 복사해 [두 사이트가 표시](screenshots/validation/fallible-profile-identities.png)되며, `sessions.toml`에 서로 다른 16자리 ID가 저장되는 것을 확인했다. 기존 설정 형식은 바꾸지 않는다.
