## 이슈 244 호스트 인증서

[`Authorities::verify`](../crates/playterm-net/src/host_certificate.rs)는 principal을 완전 일치로만 비교했다. OpenSSH의 [`sshkey_cert_check_host`와 `sshkey_cert_check_authority`](https://github.com/openssh/openssh-portable/blob/master/sshkey.c)는 호스트 검증에 wildcard를 사용한다. 기존 known_hosts용 `wildcard_match`를 principal에도 적용했다.

`*`·`?`와 대소문자 비교를 지원하며 빈 principal은 계속 거부한다. CA 범위, 서명, 유효 기간, 인증서 종류, 필수 옵션, 폐기 검증을 유지한다. wildcard를 허용한다는 이유로 신뢰하지 않는 CA나 일반 키 TOFU로 우회하지 않는다. `*.example`의 정상 호스트·공격자 접미사·루트 도메인·다른 CA를 회귀 시험한다.

## 이슈 245 사이트 저장 충돌

[`ProfileStore`](../crates/playterm-config/src/profiles.rs)는 변경 후 메모리 전체를 원자적으로 저장했다. 원자적 교체는 파일 잘림을 방지하지만 다른 프로세스의 변경을 보존하지 않는다. 같은 프로세스의 분리 창은 앱의 저장소 하나를 공유하므로, 충돌의 핵심 대상은 별도로 실행한 앱 프로세스다.

`sessions.toml.lock`을 획득하고 최신 파일에 해당 연산을 적용한 뒤 저장한다. 사이트 추가·삭제뿐 아니라 템플릿과 폴더 생성·이동·이름 변경·삭제도 같은 경계를 사용한다. 연산이나 저장이 실패하면 기존 메모리 상태를 유지한다. 사이트 저장 실패 뒤 비밀번호를 삭제·재바인딩하거나 연결하는 후속 동작도 중단한다.

식별자가 없는 구형 파일은 잠금 안에서 식별자를 한 번 생성해 저장한다. 그렇지 않으면 창마다 같은 사이트에 다른 식별자를 부여할 수 있다. 사이트 관리 창을 새로 열 때 목록을 다시 읽되, 이미 편집 중인 창의 초안은 유지한다. 저장 실패 시에도 초안을 유지하고 재시도할 수 있으며, 사이트 삭제·복제에 실패한 뒤에는 볼트의 삭제·복사를 진행하지 않는다.

서로 다른 항목의 변경은 보존되지만 같은 사이트를 두 프로세스에서 편집하면 나중에 저장한 사이트 내용이 적용된다. 별도 프로세스의 사이드바를 실시간으로 갱신하는 기능과 `settings.toml`의 동시 편집은 남아 있다. 같은 항목의 충돌 감지가 필요하면 사이트별 revision과 충돌 UI를 별도로 추가해야 한다.

회귀 시험은 오래된 저장소 두 개의 추가·삭제·폴더·템플릿 변경, 잠금 시간 초과, 손상된 파일, 구형 식별자, 별도 프로세스 두 개의 동시 추가 20건을 다룬다.

## 이슈 246 구형 SSH 알고리즘

[`connect_ssh`](../crates/playterm-net/src/ssh.rs)의 기본 선호 목록에는 요청된 SHA-1 KEX·MAC와 AES-CBC가 없다. 저장 프로필과 연결 인자에 `ssh_legacy_algorithms`를 추가하고 사이트 고급 설정에서 켤 수 있게 했다. 구형 파일에는 기본적으로 꺼진 값이 적용된다.

켠 사이트에만 group14-sha1·group1-sha1, AES-128/192/256-CBC, HMAC-SHA1 및 ETM 변형을 기존 목록 뒤에 추가한다. 현대적인 알고리즘을 우선하고 화면에 위험을 표시한다. 점프 호스트는 자신의 저장 사이트 설정을 사용하며, 대상 사이트의 옵션이 점프 호스트로 전파되지 않는다. 호스트 키 신뢰와 RSA 개인 키 파일 서명 차단 정책도 유지한다.

루프백 서버를 각각 group14-sha1 또는 group1-sha1 + aes128-cbc + hmac-sha1만 제공하도록 제한해 기본값의 거부와 명시적 허용 후 로그인·데이터 송수신을 검증한다. 실제 Cisco/스위치의 구현 차이는 #194의 장비 시험으로 확인해야 한다. 3DES와 임의 알고리즘 순서 편집은 이번 옵션에 포함하지 않는다.

## 이슈 247 SSH 인증 확장

최초 검토 당시 [`ssh_auth.rs`](../crates/playterm-net/src/ssh_auth.rs)는 에이전트 인증서 identity를 건너뛰었고 사용자 인증서 파일과 에이전트 포워딩도 없었다. 후속 1차 변경에서 파일 지정·개인 키 옆 `-cert.pub` 자동 검색·에이전트 인증서 인증을 추가했다. 일반 키와 인증서는 별도로 중복을 제거하고, 추가 인증에 이미 사용한 키를 다시 제시하지 않는다. 인증서+OTP와 기존 RSA 파일 서명 차단도 유지한다.

에이전트 포워딩은 기본 끔·사이트별 경고를 제공한다. 대화형 대상 세션에만 허용하며 점프 호스트나 요청하지 않은 세션의 agent 채널은 거부한다. 연결 시 선택한 에이전트를 고정하고 각 중계에 `session-bind`를 전달한다. SSH handler의 작업 집합으로 중계를 관리해 종료 시 중단하며, 동시 중계는 세션당 16개로 제한한다. 오래된 에이전트의 명시적인 확장 거부는 허용하므로 해당 에이전트에 목적지 제한 기능이 있다고 보장하지 않는다.

명시한 인증서의 해석 실패는 연결 오류이며, 해당 인증서가 거부됐다고 같은 키를 일반 키로 다시 제출하지 않는다. 자동 검색 인증서와 에이전트 identity에는 일반 키 fallback을 유지한다. 인증서의 CA·principal·유효 기간·권한은 서버가 검증한다. 루프백 회귀 시험에 더해 `scripts/test-openssh.sh`에 실제 OpenSSH 파일/에이전트 인증서와 포워딩 서명의 통합 시험을 추가했다. 실행 결과는 후속 PR의 검증 기록을 기준으로 한다.

Windows 전체 워크스페이스 시험, 엄격 Clippy, SSH 루프백 56개와 UI 저장 시험을 통과했다. 실제 앱에서도 인증서 경로와 [포워딩 경고](screenshots/validation/ssh-user-certificate-agent-forwarding.png)를 확인하고, 옵션의 끔/켬을 저장한 `sessions.toml`의 값을 대조했다. 로컬 프롬프트의 `ssh -A`·`-a`도 지원한다. 이 1차 변경만으로 #247 전체를 완료 처리하지 않는다.

GSSAPI는 Windows SSPI/macOS·Linux Kerberos 제공자, 자격 증명 위임 정책, 서버 식별과 통합 시험 환경을 먼저 정해야 한다. PKCS#11/FIDO2는 앱의 직접 장치 연동과 외부 에이전트에 위임하는 사용을 구분해야 한다. 직접 장치 코드가 없다는 사실만으로 모든 에이전트 기반 하드웨어 키 조합이 불가능하다고 단정하지 않는다. 이 조합의 실제 호환성은 아직 검증하지 않았다.

## 이슈 248 볼트 수명주기

[`Vault`](../crates/playterm-config/src/vault.rs)는 생성·해제·잠금·항목 변경·초기화를 지원하지만 재키잉 API는 없다. 초기화는 기존 데이터를 이동시키므로 비밀번호 변경의 대체 기능이 아니다.

비밀번호 변경은 기존 `vault.toml.lock` 안에서 최신 파일을 읽어 기존 비밀번호로 검증하고, 새 salt·키·nonce로 모든 항목과 대상 바인딩을 재암호화한 뒤 원자적으로 저장해야 한다. 다른 창에서 이미 잠금을 푼 키로 저장하는 경우의 거부와 재해제 동작도 필요하다. 실패·취소·동시 변경에서 기존 파일 보존을 시험해야 한다.

자동 잠금은 UI 입력 기준의 유휴 시간, 최소화, 절전의 의미를 각각 정해야 한다. 잠금 시 볼트뿐 아니라 탭·대기 중 작업의 비밀번호 복사본, 진행 중인 파생 작업 취소를 함께 다뤄야 한다. OS 키 저장소는 Windows DPAPI/Hello와 macOS Keychain의 정책·사용자 인증·프로필 이동·복구 요구를 별도 기능으로 설계한다. 세 기능 모두 미구현이다.

## 이슈 249 붙여넣기와 시리얼

[`view::paste`](../crates/playterm/src/view.rs) → [`Session::send_text`](../crates/playterm/src/session.rs)는 붙여넣기 전체를 한 번에 보낸다. [`serial.rs`](../crates/playterm-net/src/serial.rs)의 BREAK는 300ms이며 공유 시리얼 타입은 포트·baud·데이터 비트·패리티·정지 비트·흐름 제어만 가진다. 가져오기에서 지원하지 않는 Mark/Space·DSR/DTR은 안내하고 대체값을 사용한다.

우선 구현 단위는 사이트별 줄 단위 붙여넣기 지연이다. UI에서 sleep하거나 각 줄마다 독립 태스크를 생성하면 전송 순서·취소·재접속에서 문제가 생긴다. 세션의 순서 있는 전송 큐에 넣고 연결 종료 시 대기분을 취소해야 한다. 일반 키 입력·다음 붙여넣기·매크로·동시 입력과의 순서를 정하고 bracketed paste와 CRLF를 보존해야 한다. 문자 지연은 UTF-8/CP949의 한 문자를 바이트 중간에서 나누는 정책까지 검토해야 한다.

DTR/RTS 초기값·실행 중 토글, BREAK 길이, local echo는 독립 설정이다. 하드웨어 흐름 제어와 RTS 수동 제어의 충돌 및 포트 미지원 오류를 다뤄야 한다. 가상 시리얼 시험과 실제 장비 검증을 구분한다. 이 기능들은 미구현이다.

## 이슈 250 프록시와 프로토콜 및 인코딩

[`Protocol`](../crates/playterm-types/src/protocol.rs)은 SSH/Telnet/Serial/RDP 네 종류이며 [`Charset`](../crates/playterm-term/src/charset.rs)은 Auto/UTF-8/CP949다. Telnet은 평문 TCP이고 클라이언트 HTTP CONNECT/SOCKS 연결 계층은 없다. SSH의 `-D`는 해당 연결의 클라이언트 프록시 설정을 대신하지 않는다.

프록시는 SSH·Telnet의 TCP 연결 전 단계로 분리하고 인증정보는 볼트로 관리해야 한다. 원격 DNS 사용 여부, IPv6, 시간 제한·취소, 점프 호스트와 함께 쓰는 규칙을 정해야 한다. Telnet TLS는 인증서 이름·신뢰 체인 확인과 실패 시 평문으로 전환하지 않는 정책이 필요하다. raw는 Telnet의 IAC 해석·이스케이프를 거치지 않는 독립 전송이어야 한다. 현재 Telnet 협상이 수동이라는 이유로 raw와 동일하다고 취급할 수 없다.

추가 인코딩은 입력 인코더·스트리밍 출력 디코더·가져오기·UI를 함께 확장하고 분할된 다중 바이트와 표현 불가능한 문자를 시험한다. 기존 Auto의 UTF-8/CP949 판별을 임의로 다국어 감지로 확장하지 않는다. rlogin을 포함한 새 프로토콜과 프록시는 모두 미구현이다.

## 이슈 251 터미널 생산성

[`palette.rs`](../crates/playterm-term/src/palette.rs)의 내장 테마는 **8개**다. 원 리뷰의 7개는 코드와 다르다. 사용자 팔레트 편집이 없다는 결론은 맞다. [`keys.rs`](../crates/playterm/src/keys.rs)는 고정 단축키 표와 일부 끄기 설정을 제공하고, [`toolbar.rs`](../crates/playterm/src/toolbar.rs)는 고정 도구 모음이다. 기존 매크로와 명령 입력창도 있지만 사용자 버튼 배치·키맵 편집과는 다르다.

키워드 강조·타임라인 녹화·링크 실행은 미구현이다. OSC 8 파싱만으로 URL 실행까지 지원하는 것은 아니다. 링크를 추가할 때는 명시적 사용자 클릭과 허용 scheme, 표시 내용과 실제 목적지 확인을 설계해야 한다. 키맵은 앱 단축키·IME·프로그램의 마우스/키 모드와 충돌하지 않게 해야 하고, 강조는 정규식 비용과 그리기 성능을 측정해야 한다. 녹화는 입력 비밀정보·저장 형식·용량 제한·재생 시 제어 시퀀스의 부작용을 다룰 별도 기능이다.

자동 재접속·시작 시 탭 복원은 #252와 중복되므로 그쪽에서 하나의 구현으로 추적한다. 닫은 탭 다시 열기는 이미 있지만 앱 재시작 복원과는 다르다.

## 이슈 252 운영 자동화와 기업 배포

현재 [`Session::reconnect`](../crates/playterm/src/session.rs)와 닫은 탭 다시 열기는 수동 동작이다. GUI의 URL 실행과 대화형 매크로는 있으나 헤드리스 명령 실행·SFTP CLI, 시작 시 세션 복원, 자동 재접속 정책은 없다.

자동 재접속은 실패 종류를 구분해야 한다. 사용자가 끊은 연결·인증 취소·호스트 키 변경을 무조건 재시도하면 안 된다. 횟수·백오프·사용자 중단과 로그인 매크로 재실행 정책을 정하고, 전송 중 재접속이 명령 재실행으로 이어지지 않는지 시험해야 한다. 세션 복원은 사이트 ID와 창·탭 배치를 저장하되 비밀번호·OTP·진행 중 명령은 저장하지 않는 설계가 우선이다.

헤드리스 CLI는 출력·종료 코드·비대화형 인증·호스트 키 확인 실패를 명시적으로 정의해야 한다. MSI/GPO/ADMX·관리 설정의 우선순위·감사 로그·FIPS는 각각 별도 배포 및 운영 기능이다. 검증할 암호 모듈과 운영 플랫폼이 정해지지 않은 상태에서 FIPS 지원을 선언하지 않는다. 서명·공증은 기존 #192, 장애 시험은 #195와 연결한다. 이슈의 신규 기능은 미구현이다.

## 이슈 253 보안 보강

Windows에서는 [`x11.rs`](../crates/playterm-net/src/x11.rs)가 `PLAYTERM_XAUTH`에 지정한 절대 경로만 실행한다. 값이 없거나 상대 경로이면 PATH 검색 없이 실패하며, untrusted 쿠키 생성 실패 시 기존의 연결 거부 정책을 유지한다. Unix의 기본 PATH 실행은 유지하고 절대 경로 지정도 지원한다.

Unix 개인 키 권한은 열린 파일의 metadata로 검사해 다른 사용자에게 읽기·쓰기·실행 권한이 있으면 `chmod 600` 안내를 낸다. 호환성을 위해 이번 정책은 경고이며 강제 거부가 아니다. 자동 로그인 입력란은 활성 여부와 관계없이 평문 저장과 `{password}` 사용을 안내한다. 비밀번호를 휴리스틱으로 추측해 안전하다고 오인하게 하는 대신 모든 리터럴의 저장 특성을 명시한다.

손상된 설정은 [`AppSettings::load_preserving`](../crates/playterm-config/src/settings.rs)에서 고유한 `.broken` 파일로 복사하고 디스크에 동기화한 뒤 기본값을 제공한다. 백업·읽기 실패는 앱 시작 오류로 반환하므로 원본을 보존하지 못한 채 기본값으로 덮어쓰지 않는다. 기존 백업을 덮어쓰지 않는다.

[`playterm-sign`](../crates/playterm-sign/src/main.rs)의 환경변수·파일에서 읽은 키 문자열, hex 키 문자열과 디코딩한 바이트 배열은 `Zeroizing`으로 관리한다. hex 오류 도중의 부분 버퍼도 대상이다. ring 내부의 키 객체와 생성 문서, OS 환경변수 전체의 메모리까지 지운다는 보장은 하지 않는다.

## 이슈 254 문서와 사용하지 않는 인자

[`main.rs`](../crates/playterm/src/main.rs)의 `--open`은 읽은 파일을 삭제하는 내부 경로였지만 현재 새 창 흐름의 호출자가 없다. 이를 제거하고 알 수 없는 옵션을 오류로 처리한다. 제거된 옵션 뒤의 파일을 읽거나 삭제하지 않는 회귀 시험을 추가했다. 공개 설정 라이브러리의 TOML 변환 API는 유지하되 잘못된 새 창 전달 용도 설명을 정정했다.

[`windows.rs`](../crates/playterm/src/app/windows.rs)의 분리는 같은 프로세스에서 세션을 이동하므로 연결·비밀번호 상태를 공유한다. 한국어·영어 README를 이 동작으로 정정하고 RDP 클립보드·폴더·프린터 공유의 Windows 제한을 명시했다. 로그의 평문 append, 순환·보존 기간 제한 부재와 민감정보 가능성도 설명한다.

공급망 지적은 일부만 현재 코드에 해당한다. `ci.yml`의 MSRV 작업과 `quality.yml`의 일부 액션은 이미 SHA로 고정되어 있고 다른 CI·릴리스 작업에는 태그 참조가 남아 있다. master에는 `deny.toml`이 없다. [`security-rsa-223.md`](security-rsa-223.md)의 검사 실패는 2026-11-06의 기록이며 이번 검사로 갱신한 결과가 아니다. #207/#221과 중복되는 정책 변경·취약 의존성 처리는 이 변경에 섞지 않는다. 공급망 검사를 통과했다고 주장하지 않는다.

## 이슈 255 후속 진행 순서

다음 구현은 #249의 붙여넣기 큐와 시리얼 제어를 독립적으로 진행하고, #248의 재키잉·자동 잠금, #247의 사용자 인증서·에이전트 포워딩을 각각 분리한다. #250은 연결 계층과 인코딩을 분리하며 #251/#252의 복원·재접속 중복은 한곳에서 처리한다. 기능마다 설정 호환성, 실패·취소, 비밀정보 처리와 사용자 화면까지 검증한 뒤 완료로 표시한다.

실제 구형 네트워크 장비와 OpenSSH, macOS/Linux 네이티브 흐름, 하드웨어 키·Kerberos·기업 배포 환경 검증은 해당 기능의 완료 조건에 포함한다. 루프백 시험을 실장비 검증으로 대체하지 않는다.

## 검증

Windows 11 ARM64, Rust 1.99.1에서 `cargo test --locked --workspace`가 통과했다. 별도 프로세스의 프로필 저장, 호스트 인증서, 구형 알고리즘의 루프백 로그인·송수신, 설정 손상 복구와 실제 서명 CLI의 검증·변조 거부 시험을 포함한다. OpenSSH 데몬·실제 시리얼·ZMODEM 외부 도구·대화형 fixture 등 명시적 ignored 시험은 실행 완료로 세지 않는다.

`cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo build --locked -p playterm`도 통과했다. 화면 회귀 시험은 다른 프로세스의 사이트 재읽기·구형 SSH 옵션 저장, 저장 실패 후 초안 유지와 재시도를 포함한다. 호스트 인증서 루프백 시험에 wildcard principal을 추가해 별도로 통과했다.

실제 Windows 앱도 별도 `PLAYTERM_CONFIG_DIR`와 가짜 사이트로 실행했다. 사이트 관리 창에서 구형 SSH 옵션을 끄고 저장한 파일의 `false`, 다시 켜고 저장한 `true`를 확인했고, [한글 옵션과 경고 화면](screenshots/validation/review-244-255-ssh.png)을 확인한 뒤 앱을 정상 종료했다. 이것은 UI·저장 검증이며 실제 장비 연결 시험은 아니다.
