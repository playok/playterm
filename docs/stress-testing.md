# 부하와 장애 시험

짧은 시험은 반복 실행 가능성을 확인한다. 8~24시간 시험은 별도 테스트 장비에서 실행하며, 짧은 시험 결과만으로 장시간 안정성을 판정하지 않는다.

## 조건과 합격 기준

앱 태그·커밋·작업 트리 변경, OS 빌드·아키텍처, CPU/RAM, 렌더러, 글꼴, 스크롤백, 출력 속도, 서버 버전을 먼저 고정한다. 로그·CSV·화면의 시각도 함께 남긴다. 다른 프로그램 부하는 최소화한다.

다음 값은 첫 시험 전에 사용하는 초기 기준이며, 제품 성능 보장값이 아니다. 초기 5분을 예열로 제외하고 1/10/30탭 각각 측정한다.

| 항목 | 사전 합격 기준 |
|---|---|
| UI | 입력→에코 p95 250 ms 이하, 취소 1초 이내 반응, 2초 이상 화면 정지 없음 |
| 종료 | 테스트 연결이 있는 앱 종료 5초 이내, 로컬 포워딩 리스너와 소켓 종료 |
| 메모리 | 예열 이후 같은 부하에서 1시간당 private bytes 증가 10% 이하. 반복 연결/종료 100회 뒤 60초 휴지 후 기준 +20% 이하 |
| 핸들·스레드·소켓 | 100회 반복 후 기준 대비 핸들 +20, 스레드 +5, 활성 테스트 소켓 0. 단조 증가 시 원인 분석 |
| 파일 보존 | 실패·취소·단절 후 기존 파일 SHA-256 일치, 잘린 파일을 완성 파일로 노출하지 않음 |
| 처리량 | 같은 장비의 초기 기준선 대비 20% 이상 지속 저하 시 보류. CPU와 처리량을 같이 기록 |

RSS/작업 집합만의 증가는 누수 판정에 쓰지 않는다. private bytes, allocator 고수위, OS 파일 캐시, 대기 큐가 쉬는 동안 회복되는지 비교한다. 기준을 완화할 때는 재시험 전에 이유와 변경값을 기록한다.

## 짧은 시험

1. `python scripts/stress-server.py --directory target/stress --seconds 600`으로 loopback 전용 가짜 출력 서버를 실행한다. `target/stress/url.txt`의 URL을 실제 앱에서 1/10/30개 탭으로 연다. 기본 출력은 탭당 약 64 KiB/s다.
2. `scripts/measure-playterm.ps1 -AppId <PID> -OutputPath target/stress/metrics.csv -Seconds 60`으로 작업 집합·private bytes·CPU·스레드·핸들·응답 상태를 수집한다. 입력과 탭 전환을 실제 창에서 조작하고 화면 및 입력→에코 지연을 별도로 기록한다. 샘플러는 UI 지연·처리량·소켓 수를 자동 측정하지 않는다.
3. `--disconnect-after 10`인 별도 서버에서 단절 표시와 재접속을 확인한다. `stop` 파일로 서버를 종료할 수도 있다. `server-stats.json`의 연결·전송량·입력 수를 대조한다.
4. 실제 SSH에서 연결/종료/재접속 100회와 `-L/-R/-D` 종료를 반복한다. SFTP 1 GiB 가짜 파일 전송 중 취소·서버 중단·지연을 주입하고 기존 파일 해시를 확인한다. 전송 정지 상태에서도 취소가 동작해야 한다.
5. RDP를 반복 크기 변경·탭 재활성화하면서 닫는다. 테스트 VM에서 절전/복귀·네트워크 전환 후 상태와 재접속을 검사한다. OS 전체 절전이나 네트워크 변경은 다른 작업에 영향을 주므로 테스트 장비에서 수행한다.

## 장시간 시험

`stress-server.py --seconds 86400`과 `measure-playterm.ps1 -Seconds 86400 -IntervalSeconds 30`으로 최대 24시간 수집할 수 있다. 서버와 샘플러는 별도 터미널에서 실행한다. 8시간과 24시간 종료 지점에 UI 입력, 취소, 자원 휴지 후 회복, 파일 해시를 확인한다. macOS에서는 동일한 절차로 실제 앱을 구동하고 `ps`·Activity Monitor 및 `lsof`의 RSS/CPU/스레드/소켓을 기록한다.

결과는 [검증 기록](validation.md)에 환경·기준선·최대값·종료값·실행시간·통과/보류·증거 경로를 남긴다. 실패를 발견하면 재현 가능한 조건과 로그를 별도 결함 이슈에 연결한다. 8시간 이상 실행과 절전/복귀, 실서버 SFTP 장애, RDP 부하 검증이 끝나기 전에는 #195를 완료로 간주하지 않는다.
