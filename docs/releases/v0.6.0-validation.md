# v0.6.0 게시 후 검증

2026-11-06 09:39:55 KST에 [v0.6.0](https://github.com/playok/playterm/releases/tag/v0.6.0)을 정식 릴리스로 게시했다. 태그의 소스는 `c807c1fbecec0edf4247fb9186526c6a64ac28df`이며 #203까지의 수정과 #204의 버전·변경 내역 준비를 포함한다. 아래 검증 기록은 게시 후 문서이며 태그의 바이너리를 바꾸지 않는다.

## 빌드와 공개 파일

[릴리스 워크플로 42133404799](https://github.com/playok/playterm/actions/runs/42133404799)의 Windows·macOS·publish 작업은 모두 성공했다. [준비 PR 204 CI](https://github.com/playok/playterm/actions/runs/42133000646)와 태그 커밋의 [master CI](https://github.com/playok/playterm/actions/runs/42133397752)도 성공했다.

- 공개된 Windows 기본/UPX × ARM64/x64 ZIP 4개와 macOS ARM64/x64 ZIP 2개를 다시 다운로드했다. 여섯 SHA-256이 공개 체크섬과 일치했다. [기계 판독 결과](v0.6.0-verification.json)에 실제 해시를 보존했다.
- 공개 `SHA256SUMS.txt`의 Ed25519 서명을 앱 공개 키로 검증해 `signature OK`를 확인했다. 개인 키 값은 조회하지 않았다.
- Windows 네 실행 파일의 버전 리소스는 모두 `0.6.0`이며 PE 아키텍처가 패키지 이름과 일치했다. 네 파일 모두 Authenticode `NotSigned`, 게시자·타임스탬프 없음이었다.
- macOS 두 ZIP의 앱 버전은 `0.6.0`이고 Mach-O 아키텍처는 각각 ARM64/x64였다. 최종 ZIP에서 추출한 앱은 CI에서 `codesign --verify --deep --strict`, designated requirement 검증을 통과했다. 두 앱은 ad-hoc 서명이며 Developer ID 서명·공증된 앱이 아니다. 공개 ZIP은 검증한 CI 아티팩트와 해시도 일치했다.
- GitHub latest 릴리스가 `v0.6.0`임을 확인했다. 본문에 사용자 설명 네 섹션, v0.5.0 비교 링크, 실제 서명 상태, 6개 패키지 안내와 체크섬·서명 안내가 보존됐고 초안 표시는 없었다.

## 공개 Windows 패키지의 실제 로그인

초기 검사는 Windows 잠금 화면 때문에 OTP 입력 전에 중단됐다. 이후 잠금 해제된 Windows ARM64에서 같은 공개 ZIP의 실행 파일 네 개를 각각 격리된 설정으로 실행해 최종 로그인까지 검증했다. 가짜 loopback SSH 서버는 서로 다른 Ed25519 키 두 개의 서명을 요구한 다음 OTP `123456`을 요구했다. 각 앱에서 OTP 창에 직접 입력한 뒤 `Connected`와 원격 `welcome` 출력을 확인했다. 네 실행의 서버 기록에는 두 공개 키 서명 요청이 각각 네 번, keyboard-interactive 요청이 합계 여덟 번(시작과 응답)이 있었다. 실제 사용자 키·서버·암호는 사용하지 않았다.

| 공개 패키지 | 두 키 + OTP 후 실제 연결 | 화면 |
| --- | --- | --- |
| Windows ARM64 기본 미압축 | 통과 | [Connected](../screenshots/validation/v060-arm64-connected.png) |
| Windows ARM64 UPX | 통과 | [Connected](../screenshots/validation/v060-arm64-upx-connected.png) |
| Windows x64 기본 미압축 | 통과, ARM64 에뮬레이션 | [Connected](../screenshots/validation/v060-x64-connected.png) |
| Windows x64 UPX | 통과, ARM64 에뮬레이션 | [Connected](../screenshots/validation/v060-x64-upx-connected.png) |

이는 네이티브 x64 OS 시험이나 백신 탐지율 비교가 아니다. 네 파일의 프로세스 실행과 로그인은 성공했지만, UPX 제거가 백신 오탐을 없앤다고 보장하지 않는다.

## 공식 v0.5.0 UPX에서 실제 자동 업데이트

공식 v0.5.0 ARM64 UPX 실행 파일의 격리 사본에서 `Help → Check for updates`를 열었다. 실제 공개 v0.6.0 본문의 한글 설명과 링크가 표시되는 것을 [확인했다](../screenshots/validation/v060-public-update.png). v0.5.0의 기존 표시기는 Markdown 문법과 URL을 그대로 보여 주므로, 이를 새 버전의 링크 정리 표시기 검증으로 기록하지 않는다. 새 표시기의 별도 개발 빌드 검증은 [기존 기록](../validation.md)에 있다.

`Update`로 실제 공개 파일을 내려받아 설치 준비 완료를 확인하고 `Restart now`를 실행했다. 새 프로세스의 파일·제품 버전은 `0.6.0`이고, 설치된 실행 파일의 SHA-256은 공식 ARM64 기본 미압축 ZIP에서 추출한 실행 파일과 일치했다. [재시작 후 About 화면](../screenshots/validation/v060-updated-about.png)에서도 `Version 0.6.0`을 확인했다. 따라서 기존 UPX 사용자도 이번 업데이트 후 기본 미압축 변형으로 전환되는 정책을 실제 경로에서 확인했다.

## 남은 범위와 로컬 증거

로컬 산출물은 `target/release-validation/v0.6.0/`에 있다. `published/`에 공개 ZIP·서명·체크섬·개별 Windows 검사 JSON, `mac-artifact/`에 macOS 버전·아키텍처 검사 JSON, `updater-upx/`에 실제 다운로드·설치·재시작 화면이 있다. 최종 패키지별 OTP·연결 화면과 서버 요청 기록은 `target/gui-validation/060-public-auth/`에 있다. 초기 `gui/`의 OTP 창만을 로그인 성공 증거로 확대하지 않는다.

macOS 네이티브 GUI, 깨끗한 OS 첫 실행, 정식 서명·공증과 실장비·절전 복귀 검증은 별도 이슈 #192·#194·#195에 남아 있다. 이 기록은 기존 공개 파일의 검사이며 새 태그나 바이너리를 게시하지 않았다.
