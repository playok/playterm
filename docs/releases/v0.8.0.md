# playterm v0.8.0

## Highlights

- UI·도움말·연결 오류를 리소스 기반 다국어 구조로 전환하고, 영어·한국어에 일본어(`ja`), 중국어 간체(`zh-CN`), 스페인어(`es`), 브라질 포르투갈어(`pt-BR`), 독일어(`de`), 프랑스어(`fr`), 중국어 번체(`zh-TW`), 러시아어(`ru`)를 추가했습니다. 각 언어는 984개 문구를 제공합니다. 설정에서 즉시 미리보기·취소·저장할 수 있으며, 새 설정은 OS 언어를 따릅니다. #264, #265, #266
- 지원하는 10개 언어 모두 README 진입점을 제공합니다. 새 언어별 사용 가이드에는 설치·접속·파일 전송·인증·설정·빌드 안내와 상세 문서 링크를 담았습니다. #267
- 접속 인코딩에 Shift_JIS·EUC-JP·GBK·GB18030·Big5·Windows 코드 페이지·ISO-8859·KOI8·Mac 문자셋을 추가했습니다. PuTTY·Xshell·SecureCRT에서 지원 인코딩을 가져오고 사이트별 선택을 저장합니다. #264
- 사이트별 SSH 에이전트 포워딩(`-A`)과 OpenSSH 사용자 인증서를 지원합니다. 포워딩은 기본적으로 꺼져 있고 점프 호스트에는 전달하지 않습니다. 사용자 인증서는 파일 지정·개인 키 옆 자동 검색·에이전트 identity를 지원합니다. #247
- 사이트별 **이전 SSH 장비 호환** 옵션을 추가했습니다. 켠 사이트에만 SHA-1 키 교환·MAC와 AES-CBC를 허용하며 현대적인 알고리즘을 우선합니다. #246

## Fixes

- 설정창 하단의 기본값 복원 버튼을 왼쪽으로, 취소·확인(저장) 버튼을 오른쪽으로 배치했습니다.

- 다른 운영체제에서 가져온 사이트의 SSH 에이전트 경로가 현재 플랫폼과 맞지 않으면 `SSH_AUTH_SOCK`으로 폴백합니다. Windows 경로의 대소문자와 드라이브 경로도 구분합니다. #258
- 읽기 전용 설정 디렉터리에서도 정상 설정과 사이트 목록을 읽습니다. 손상된 세션 파일은 잠금 안에서 재확인하고 고유한 백업으로 옮겨 다른 창의 정상 저장을 보호합니다. #259
- 여러 프로세스가 사이트·폴더·템플릿을 저장할 때 최신 파일을 잠금 안에서 읽고 해당 변경만 적용합니다. 사이트 관리 창을 열 때 목록을 갱신하며, 저장 실패 시 메모리와 볼트의 후속 변경을 막습니다. #245
- SSH 호스트 인증서 principal의 `*`·`?` wildcard를 지원합니다. 빈 principal과 신뢰하지 않는 CA는 계속 거부합니다. #244
- 손상된 `settings.toml`을 고유한 `.broken` 파일로 보존한 뒤 기본값을 사용합니다. 보존에 실패하면 원본을 덮어쓸 수 있는 상태로 시작하지 않습니다. #253
- Unix 개인 키 파일의 권한이 다른 사용자에게 열려 있으면 안내하고, 자동 로그인 입력란에는 평문 저장과 `{password}` 사용을 안내합니다. 릴리스 서명 도구의 키 버퍼는 사용 후 지웁니다. #253
- 긴 번역에서도 글꼴 미리보기 샘플을 확인할 수 있도록 오류 문구와 문자 샘플을 분리했습니다.

## Compatibility and update notes

- 기존 언어 선택은 유지됩니다. 설정에는 언어 코드를 저장하며, 사용할 수 없는 언어는 영어로 대체합니다. 번체와 간체는 별도 선택입니다. 포르투갈어의 브라질 외 지역과 문자 체계가 지정되지 않은 `zh`·`zh-HK`·`zh-MO`는 자동으로 다른 지역 번역을 선택하지 않습니다.
- UI 언어와 접속 인코딩은 독립적입니다. 자동 인코딩 감지는 UTF-8/CP949로 유지되며, 다른 인코딩은 직접 선택해야 합니다. UTF-16과 ISO-2022-JP는 지원 대상이 아닙니다.
- 에이전트 포워딩을 켜면 원격 서버가 로컬 에이전트에 인증 서명을 요청할 수 있으므로 신뢰하는 서버에만 사용하세요. 명시한 사용자 인증서의 읽기·해석 실패나 포워딩 준비 실패는 연결 오류입니다. OTP와 기존 로컬 RSA 개인 키 파일 서명 제한은 유지됩니다.
- Windows의 X11 쿠키 조회·생성에는 `PLAYTERM_XAUTH`에 신뢰하는 `xauth.exe`의 절대 경로를 지정해야 합니다. 현재 디렉터리나 PATH에서 실행 파일을 찾지 않습니다. #253
- 사용하지 않는 내부 인자 `--open`을 제거했습니다. 새 창으로 이동은 같은 프로세스 안에서 연결을 유지하며, 창 사이의 비밀번호 격리 경계가 아닙니다. #254
- 소스 빌드는 Rust 1.95 이상이 필요합니다. Windows 앱 내 업데이트 후에는 재시작해야 합니다. 기본 Windows 패키지는 미압축이며, UPX 사용자의 자동 업데이트도 기본 패키지를 사용합니다. macOS는 새 릴리스 다운로드 페이지를 안내합니다.

## Known limitations

- GSSAPI/Kerberos·PKCS#11·FIDO2 직접 연동 등 #247~#252의 후속 기능은 이번 릴리스에서 모두 구현된 것이 아닙니다. [검토 결과와 후속 조건](https://github.com/playok/playterm/blob/v0.8.0/docs/review-244-255.md)을 확인하세요.
- 로컬 RSA 파일 서명 차단은 임시 완화이며 의존성 취약점의 공식 해결을 뜻하지 않습니다. 외부 에이전트의 보안과 RDP의 개인 키 연산 도달성에는 별도 검증 범위가 남아 있습니다. [RSA 완화와 잔여 위험](https://github.com/playok/playterm/blob/v0.8.0/docs/security-rsa-223.md)을 참조하세요. 공급망 정책 PR #221의 변경은 포함하지 않습니다.
- 다국어 UI 전환·취소·저장·재시작은 macOS에서 확인했습니다. Windows/Linux의 새 언어별 실제 화면 및 원어민 전수 문구 검수는 미실행입니다. 실제 장비 콘솔·RDP/RD Gateway·절전·네트워크 전환에는 추가 검증 범위가 남아 있습니다. [호환성 표](https://github.com/playok/playterm/blob/v0.8.0/docs/compatibility.md)를 확인하세요.
- RDP 클립보드·폴더·프린터 공유는 Windows 전용입니다. 기타 프로토콜 제한은 [v0.7.0 변경 내역](https://github.com/playok/playterm/blob/v0.8.0/docs/releases/v0.7.0.md)을 참조하세요.
- 코드 서명·공증 상태와 체크섬은 아래 Downloads의 실제 빌드 결과를 확인하세요. 미서명 Windows/ad-hoc macOS 빌드에서는 SmartScreen·Gatekeeper 경고가 발생할 수 있습니다.
