# 호스트 신뢰 관리 검증 (#213)

도구 → 저장된 호스트 키·인증서에서 앱 설정 폴더의 `known_hosts`와 `known_rdp_hosts`를 표시한다. SSH 점프 호스트도 대상 이름·포트로 구분한다. SSH 마커와 해시 호스트 이름은 원문으로 식별하며, 공개 키의 SHA-256 지문을 계산한다. 잘못된 비주석 줄도 표시·삭제할 수 있다.

변경된 키는 기존처럼 접속 단계에서 차단한다. 정상적인 교체는 서버 관리자에게 새 지문을 확인한 다음 이 화면에서 기존 항목 삭제를 확인하고, 재접속 때 새 지문을 신뢰하는 두 단계다. 파일 편집이 경합하면 사용자가 확인한 줄과 일치할 때만 삭제한다. 파일 읽기 오류를 최초 연결로 처리하지 않는다.

2026-11-06 Windows ARM64에서 전체 locked 워크스페이스 테스트, strict clippy, fmt를 통과했다. 기존의 다른 알고리즘/다른 키 차단과 질문 없는 불일치 거부 통합 시험도 통과했다. 두 독립 프로세스가 준비 신호 뒤 같은 RDP 대상을 동시에 저장하는 회귀 시험은 정확히 한 줄을 남겼다. 다른 인증서를 저장하려는 시도는 파일을 바꾸지 않고 실패한다.

실제 Windows 앱에서 가짜 SSH/RDP 기록의 [목록](screenshots/validation/trusted-hosts-list.png)과 [삭제 확인](screenshots/validation/trusted-hosts-remove.png)을 확인했다. 확인 전·Esc 취소 후 SSH 파일 해시는 같았다. 확인 버튼을 누른 뒤 SSH와 RDP 항목이 각각 삭제되고 목록이 비는 것도 확인했다. 별도의 전체 앱 UI 시험은 취소 시 파일 불변, 명시적 확인 후 삭제를 자동 검증한다.

RDP 서버 자체의 화면 공유를 새로 시험한 것은 아니다. 이번 RDP 범위는 인증서 기록의 잠금·검사·관리 화면이며, 기존 TLS/인증서 테스트를 함께 실행했다.
