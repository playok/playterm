# 원격 포워딩 주소 구분 검증 (#218)

서버가 보고한 바인드 주소와 포트에 정확히 맞는 규칙을 우선한다. IP 주소 표기를 정규화하고 호스트 이름은 ASCII 대소문자를 구분하지 않는다. 빈 문자열과 `localhost`는 루프백 별칭이며, 호환 가능한 규칙이 하나일 때만 IPv4/IPv6 루프백과 연결한다. IPv4와 IPv6의 서로 다른 명시적 규칙이나 중복 규칙에서 목적지를 결정할 수 없으면 채널을 거부한다. DNS 조회로 주소를 추측하거나 포트만 보고 고르지 않는다.

2026-11-06 Windows ARM64에서 다음을 확인했다.

- `cargo test --locked --workspace`와 strict clippy/fmt.
- 실제 SSH 채널로 `127.0.0.1:port`와 `[::1]:port`를 각각 다른 대상에 연결해 A/B 표식과 왕복 데이터를 확인하는 통합 시험.
- 서버가 주소를 빈 문자열 또는 `localhost`로 보고해도 단일 루프백 규칙이 동작하는 통합 시험. 일치하지 않는 주소의 채널은 즉시 거부됨을 확인.
- IPv6 표기, 다른 포트, 다른 주소, 중복 규칙, 모호한 루프백 별칭을 검사하는 단위 시험.
- 실제 앱을 두 `-R` 인수로 실행해 같은 포트의 두 원격 리스너가 [화면에 표시](screenshots/validation/remote-forward-same-port.png)됨을 확인. 각 바인드 주소에 접속했을 때 별도 로컬 대상에서 A와 B를 각각 받았다. 시험용 설정·키·루프백 서버만 사용했다.

빈 주소가 서버 정책에 따라 공용 주소를 뜻하거나 서버가 여러 실제 주소를 같은 별칭으로 보고해 구분할 수 없는 경우에는 명시적인 바인드 주소를 사용해야 한다. 이 시험은 로컬 루프백이며 외부 장비별 `GatewayPorts` 정책 검증을 대신하지 않는다.

macOS는 추가 IPv4 루프백 별칭을 별도로 설정해야 할 수 있어, 공통 통합 시험은 기본 IPv4/IPv6 루프백을 사용한다. Windows 네이티브 시험의 두 IPv4 주소 결과는 위와 별도로 유지한다.
